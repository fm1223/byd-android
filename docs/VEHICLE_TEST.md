# 车辆选择、PIN 与门锁测试（0.2.0-dev）

## 使用

覆盖安装新版即可保留已有登录信息。单辆车自动选中；多辆车请选择目标，选择会加密保存。界面展示列表返回的车辆名称、车型、车牌、脱敏 VIN 及账号身份；没有实时门锁状态。

点击“设置／更改操作 PIN”，输入官方 App 的六位操作 PIN。验证通过才加密保存，失败不覆盖原 PIN。保存后显示 ••••••；支持移除，每辆车独立保存。临时输入 PIN 的操作不保存 PIN。

点击“解锁”或“锁车”会发送真实车辆请求。有保存的 PIN 时直接执行；未保存时提示输入 PIN。请求期间禁用按钮并串行执行，不附加身份声明、VIN 后六位或 SEND 确认。成功发送后显示“请求已发送，车辆实际状态请现场确认”，这不代表车辆已经执行成功。

退出登录清除账号、Session、车辆选择与所有保存的 PIN。覆盖安装兼容旧版账号存储，不需要重新登录。

## 流程

操作前查询列表并确认目标仍属于账号；明确 Session 失效才允许一次静默登录。PIN 校验后依次调用：

- /vehicle/vehicleswitch/verifyControlPassword
- /control/rc/remoteAwakeRequest
- /control/rc/remoteControl

授权车辆 empowerType<0 或存在 empowerId 时使用 identifierType=1，车主用 0。使用原有 WBSK、AES、签名、设备标识与 Session。PIN 采用单次大写 MD5。锁车 LOCKDOOR，解锁 OPENDOOR。

PIN 成功响应可能为空或不可解密的确认，仅验证外层成功码。唤醒与门锁兼容空、文本、JSON 确认；能识别的业务拒绝不会显示为接受。门锁请求后发生网络／解码异常显示结果未知，不重发。没有接入 remoteControlResult 查询、BYD MQTT 或自动控制。

## 已完成验证

31 项合成数据测试通过；完整请求与已在 Node 上实测成功的实现逐字节对照，覆盖车主与授权身份。还验证了多车不默认选首辆、拒绝保存错误 PIN、已存 PIN 持久恢复、临时 PIN 不保存、车辆移除阻止操作、唤醒拒绝停止、超时仅发送一次门锁请求。

Debug 构建与 Android 静态检查通过。小米 13 已覆盖安装并打开车辆页面；检查时页面显示 PIN 验证通过并已保存。开发测试没有代用户发送车辆命令。

## 手机验证

1. 检查目标车辆信息与身份。
2. 保存正确 PIN；尝试错误 PIN 时，应提示失败并保留原已保存状态。
3. 手动点击解锁／锁车，观察实际车辆及页面提示。
4. 强制停止后重开，确认车辆选择和 PIN 已保存；未保存 PIN 时操作需临时输入。

Android 上的真实门锁操作、多辆车切换、手机重启后的 PIN 恢复、授权失效及真实 Session 过期仍需要实机反馈。巴法云与后台服务属于后续阶段。

Node 对照测试夹具只包含合成账号、PIN、VIN 与令牌，不依赖真实账号，也不会访问网络。
