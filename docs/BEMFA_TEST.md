# 巴法云与后台联动（0.4.5-dev）

## 配置与使用

1. 覆盖安装新版，已有登录与 PIN 会保留。在车辆页打开“巴法云设备联动”。
2. 在巴法云 MQTT 控制台创建开关 topic，例如 car002。填写用户私钥（32 位）与 topic，选择绑定车辆。该车必须已有经过服务端验证并保存的 PIN。
3. 点击“保存设备绑定”，再点击“启动后台联动”，允许通知。看到“已连接，等待 on／off 指令”后开始测试。
4. 巴法云设备收到 on 时解锁，off 时锁车。也可向 car002/set 发布精确的 on 或 off；topic 需替换为自己的名称。不要在配置尚未确认时发送测试指令。
5. 点击页面或常驻通知的“停止”，停止连接并保存停用状态。已发送的车辆请求无法撤销；停止不会重发指令。

当前支持一个设备／topic 绑定，可在多辆车中选择目标。绑定保存明确 VIN，首页切换车辆不改变绑定目标；更换绑定需要重新启动。私钥输入隐藏，已保存后显示已加密保存，留空沿用原私钥。PIN 与私钥均保存在 Android Keystore 保护的原有加密存储中。退出登录清除绑定；移除绑定车辆的 PIN 或车辆不再属于账号时停用联动。

联动页面使用“启用后台联动”开关，开启后不重复启动，关闭后停止联动。首页与联动页均显示醒目的状态标记：绿色表示订阅完成、黄色表示连接中、红色表示断开并等待重连、灰色表示已停止或等待启动。执行车辆指令时，连接标记保持独立，不把请求发送成功当作连接成功。

## 固定连接与消息规则

mqtt.bemfa.com:9501，普通 TCP，MQTT 3.1.1，不使用 TLS，也不需要配置证书。用户私钥作为 client ID，不传用户名／密码。Android 网络配置仅允许该域名的明文连接，比亚迪接口继续使用 HTTPS。订阅 QoS 0、clean session=true，重连后重新订阅，不读取历史状态。不会发布 MQTT 消息或将车辆状态反馈到云端。

只接受匹配 topic 的精确 on/off。忽略 retain、DUP、未知载荷、未完成订阅时的消息与正在处理指令时的新消息；同方向三秒内重复消息忽略。没有指令队列，也不持久保存待执行指令。纯 on/off 不含时间戳，不能判断任意发送者自行延迟发送的消息年龄。

所有车辆操作与手动按钮共享一个串行执行器。执行前复核最新绑定、车辆权限与保存 PIN，允许在明确会话失效时进行一次静默登录，门锁请求从不自动重试。超时提示结果未知。重新连接只恢复订阅，不补发车辆命令。页面与通知显示请求发送结果，不代表实际门锁状态。

## 后台设置

联动页面增加“在通知栏显示后台联动”开关，显示系统的实际通知状态。点击进入通知设置，开启或关闭“车辆设备联动”通知，返回后同步开关；未授予通知权限时进入应用通知设置。启动服务不再重复请求通知权限，保留用户关闭通知的选择。服务继续满足前台服务要求，隐藏通知不停止联动；Android 仍可能在活动应用列表中显示服务。

Android 8+ 使用常驻前台服务；Android 14+ 声明 connectedDevice 类型。服务空闲时不持续持有 CPU 唤醒锁，仅处理指令时短暂持有并设置超时。

小米 13 建议允许通知、开启后台自启动、将省电策略设为不限制、在最近任务中锁定应用。设置入口打开系统应用信息。正常重启并首次解锁后尝试恢复此前启用的联动；系统强制停止会阻止后台恢复，必须手动重开应用。Android 与厂商省电策略仍可能中止网络连接，长时间锁屏效果需实机验证。

## 已验证与待验证

50 项 JVM 测试通过，包括真实 Paho 客户端与本机模拟 MQTT 服务器的 CONNECT／SUBSCRIBE／保留标志接收，以及绑定目标、停止／更换绑定、PIN 移除与车辆权限撤销。Debug、Release 与 Android 静态检查通过。

连接地址已改为 mqtt.bemfa.com:9501，使用普通 MQTT。本次没有使用真实巴法云私钥订阅，也没有代用户发送车辆指令。主 APK 已在小米 13 覆盖安装；手机测试包被系统安装限制拒绝，未完成前台服务生命周期仪器测试。0.4.0 的车辆、联动、设置页面已在小米 13 查看，diFansVehicleImg 图片成功显示。

待用户验证：真实订阅与 on/off 门锁操作、锁屏接收、Wi-Fi／移动网络切换、停止后不执行消息、正常重启恢复。先在页面中看到连接成功，再测试锁屏，最后验证重启。

开发者可构建 assembleDebugAndroidTest 并运行 BridgeSmokeInstrumentation。该仪器测试只检查私钥输入框与空绑定的服务创建／停止，不写绑定或发送车辆命令；有绑定时跳过空绑定服务探测。
